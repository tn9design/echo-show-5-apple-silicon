# Source preview implementation results

The integrated app, shared core, CLI and MCP build successfully on the development Mac using local temporary build staging. The expanded run executed 145 XCTest cases with the optional pinned-ROM and pinned-payload fixtures enabled: all passed, none skipped, and no failures. Tests use temporary fixtures, fake runners and isolated host PTYs; they do not connect to an Echo, create a VM, or prove unlock repeatability.

Internal unlock orchestration verifies fresh guest/artifact/device evidence before consuming approval, holds operation ownership across at most three eight-second attempts, permits two-second intervals only after the exact complete rejection, and records the five-minute powered-wait requirement before dispatch. Four fixtures cover rejection bounds, timeout/unexpected/disconnected/cancelled transfer, identity/artifact mismatch and incomplete powered waiting. It never returns unlock success. An internal authenticated guest transport is implemented, but no public live dispatcher is connected to it. The internal fixed one-second powered-wait clock passed three cancellation/timing tests using shortened fixture ticks; its timer remains independent of caller cancellation. Wait records are synchronized before dispatch, and read-only status excludes the private request identifier. A live five-minute device run remains unverified. Independent compatible TWRP verification remains required.

Source packaging now removes Python caches from the disposable copy and CI checks archive paths, symlinks, metadata, required deliverables and signing entitlements. The packaged bounded helper loads its bundled profile in an offline import check; its four metadata tests pass without device commands.

The internal supervised installation workflow now performs fresh recovery, ZIP size/hash and backup checks under operation ownership, consumes approval before wipes, preserves a private synchronized recovery log, and records installation only after reviewed success evidence and accepted reboot. Seven end-to-end fake-device fixtures cover success, changed recovery/ZIP/backups, installer/reboot failures and replay rejection. Startup remains a separate personal confirmation. The native/CLI/MCP live dispatcher is still disabled; no installation was performed during these tests.

Download results are bound to operation IDs, and existing owned directories can be reused while symlinks and regular files are rejected. Diagnostic reports allowlist profile/action labels instead of exporting arbitrary session text; native export captures exactly the displayed preview. Invalid USB plist output reports inspection unavailable, and guest readiness gives separate architecture, translation and SSH explanations. Permission-denied USB inspection still falls under unavailable inspection rather than a separately verified category.

The internal approval boundary durably consumes the exact pending request before entering its callback, rejects stale evidence and concurrent consumers, and leaves unknown outcomes requiring inspection. Six fixtures passed; no production dispatcher calls this boundary yet. Public live approval execution remains disabled. The pilot installer now requires an unambiguous hash for the exact pinned device-side ZIP, including after wipes; duplicate output stops before wiping.

CLI and MCP now expose profile-pinned publisher downloads into the private app-owned download folder. MCP returns a journaled operation ID and status progress; server input closure awaits the transfer. Three operation fixtures passed for HTTP failure, cancellation and unsafe directory rejection. This prepares downloads only, never claims Linux readiness, and has not yet been exercised through an actual MCP client or a fresh publisher download.

Internal ROM staging now checks all five backup images against their manifest before and after staging, validates the durable receipt, and records the pinned ROM hash only if the session evidence remains unchanged. Five workflow fixtures passed, including changed-device and corrupted-backup rejection. This internal operation is not exposed through the app, CLI or MCP; device-writing release gates remain disabled.

The native post-install checklist records Wi-Fi, touchscreen, audio, microphone, camera and normal reboot separately as timestamped personal observations. Five focused tests passed. Returning to recovery clears previous startup and hardware observations, including for the same device. These controls do not establish automated hardware verification; their visual runtime behavior remains unverified.

The project-authored offline protocol helper is bundled and hash-verified, removing its file picker. Client/helper hashes now come from the versioned compatibility profile. A resource test caught a missing Python file in the generated bundle; explicit copy-resource packaging fixes it and the test verifies equality with the source helper.

The Debian-only translation script now installs a persistent read-only virtiofs mount and orders binfmt-support after it. Three offline script checks and shell syntax passed. No guest restart was performed, so persistence is implemented but remains live-unverified.

Experimental app controls now request bootstrap and offline guest validation. Guest trust is persisted privately, omitted from diagnostic exports, and invalidated for readiness after managed start/stop actions. Validation reacquires serial identity before SSH, supports a changed private guest address, rejects a changed host key, stages only hash-verified validation assets and records the offline result. The app can make one bounded serial login attempt as `user` using a memory-only password. Accepted and rejected exchanges pass isolated PTY tests; the actual Debian VM flow remains unverified. A graphical-console login is not used as serial authentication.

The app now selects recovery candidates from structured ADB results. Interrupted read/backup operations require explicit reinspection of the same recovery device and invalidate prior backup/install evidence. Interrupted writes cannot use this path. Owned-VM reconciliation, start and graceful shutdown use exact ownership markers and the recorded UUID; absent or ambiguous results retain creation intent. Fresh lifecycle and input checks are recorded below; guest bootstrap and backup integrations remain live-unverified.

Owned serial-channel discovery is implemented against UTM 5.0.6's scripting dictionary and tagged source. It requires a running Apple VM, exact ownership/UUID binding and one PTY port. The explicit shared-engine bootstrap path opens the verified character device, bounds reads/writes, uses fresh challenge framing, creates a unique client key, installs its public half and pins the unchanged guest host key before SSH. Native login is available through the temporary password field. Interrupted key creation is not overwritten automatically. Guest provisioning, visual interaction and live host-key acquisition remain unverified or unfinished; no guest commands ran during these checks.

Offline CLI/MCP smoke checks passed: initialization, tool listing, ping, malformed JSON, rejection of caller paths/approval tools, isolated session creation, and rejection of installation without prerequisites.

Source packaging and shell syntax checks passed. A source ZIP includes tools, profile, app/core/interface sources, tests, skill, docs and license; it omits personal backups, VM images and credentials.

The release script now builds from its disposable local source copy as well as using local build output, and strips filesystem metadata from disposable copies only. Hardened-runtime signing applies the Apple Events automation entitlement to the app and both companions, alongside the app's existing usage description ([Apple entitlement documentation](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.automation.apple-events)). Shell syntax, entitlement plist parsing and source-archive inclusion/metadata checks passed. A production build from the extracted source archive completed successfully after allowing Xcode debug-symbol generation outside the restricted runner. This does not prove signed automation, notarization or clean-account installation; those still require distribution credentials and runtime validation.

See prototype-status.md for remaining live-validation and implementation gates. This does not mark all milestones complete.

Independent reviewers reproduced and then confirmed fixes for stale same-ROM success logs, absent backup manifests, and OpenSSH configuration paths. Revised source archive helper inclusion was independently checked.

The launch script refused to overwrite/relaunch an already-running EchoGuide instance, as intended. The new native window/button flow was not visually verified in this pass.

Measured backup progress is available in the app and private session status. Four offline transfer tests cover intermediate byte counts, corruption, transfer exceptions and mount-restoration failure. Captured bytes never substitute for size/hash verification; completion follows verified images, restored mounts and manifest creation. Live backup progress and UI rendering remain unverified.

A live fresh-workspace check on macOS 27.2 with pinned UTM 5.0.6 and the hash-matched Debian ISO exposed AppleScript error -1700: the `serial ports` record key resolved to the serial-port class. The creation script now uses the exact `SrPt` configuration field code from the shipped dictionary. A new isolated VM was created successfully, and ownership reconciliation returned its recorded UUID, Apple backend and stopped state. Earlier failed ownership intents were retained and independently found absent. No VM was booted and no Echo command ran in this check; guest install/login/readiness and the two-workspace acceptance gate remain open.

A subsequent explicit start of that isolated VM failed. The native UTM library and independent ownership inspection continued to report stopped; the Debian ISO remained selected. The first failure discarded the underlying scripting diagnostic, so its cause is unknown. Lifecycle failures now retain bounded local stderr, and the CLI exposes checked start/stop workspace operations. These operations do not imply guest readiness or authorize Echo writes. The next explicit diagnostic start returned AppleEvent timed out (-1712); this establishes a scripting timeout, not a successful boot or its underlying cause. No overlapping lifecycle command or Echo write was issued.

The native Run comparison exposed a separate UTM accessibility-action crash (EXC_BAD_ACCESS in SwiftUI accessibility button handling). An ordinary pointer click then started the same exact owned VM successfully: scripting inspection returned started and the pinned Debian GRUB installer menu was visible. This proves generated-VM bootability, but does not resolve automated scripting startup, install Debian, or validate authenticated guest readiness. Raw crash reports remain private.

Fresh-VM input validation remains open: Return and Down did not change the Debian GRUB menu after display focus. Tagged UTM source defaults Apple keyboard/pointer devices to disabled and does not expose them through its Apple configuration scripting record. The baseline therefore retains the explicit app-owned Devices setup step; no unsupported scripting property is added. This observation does not prove the configuration is ready for Debian installation.

The first fresh VM’s saved configuration independently confirms Virtualization.Keyboard and Virtualization.Pointer are Disabled. Its graceful shutdown request at GRUB returned started, correctly avoiding a claim of shutdown. A second isolated workspace was created from the same pinned ISO with a distinct VM identity; independent ownership inspection returned that recorded identity, Apple backend and stopped state. Neither workspace has completed Debian account setup or guest validation, so the two-ready-workspace acceptance gate is still open.

Async MCP backup integration passed the complete 74-test suite and isolated CLI/MCP protocol smoke checks. Backup reserves its persistent journal ID and cross-process active lock before returning, retains ownership during detached capture, and exposes progress through status. Short session transactions now allow bounded contention from status polling without weakening active-operation exclusivity. Graceful stdio EOF waits for capture; failed terminal persistence remains incomplete and requires inspection. These tests use fixtures, not live recovery transfers or two actual MCP clients.

The second stopped workspace was configured through the native UTM Virtualization pane: Keyboard Generic USB, Pointer Generic Mouse, and Enable Rosetta on Linux checked. Saved plist values were inspected independently. The app instructions now name the observed pane and option labels. Guest input response and translation execution remain unverified; saved configuration alone does not establish readiness.

After saving the second workspace’s input/translation options, the shared CLI start operation returned its exact owned UUID with started state. Native inspection showed Debian GRUB, and Down visibly moved selection from Install to Graphical install. The normal Install entry was then launched. This verifies one configured workspace’s scripted startup and keyboard response, not the cause of the earlier timeout, installed guest readiness, or Linux translation execution.

Shared publisher downloads, immutable approval prerequisite snapshots, internal ROM staging, and failure-preserving diagnostic outcomes passed the final 90-test integration run. Download fixtures cover HTTP failure, corrupt bytes, cancellation and successful verification. Staging tests currently cover rejection/parser boundaries only; a complete successful transfer fixture and live staging remain open. Approval snapshots bind profile/guest/manifest content and reject negative elapsed time or five-minute expiry, but are not single-use write grants. Public writes remain disabled. Native UI confirmation is not a security boundary against an unrestricted same-user process.

The ROM staging sequence now has optional full fixtures using the actual pinned local ROM and a fake command runner. Six staging tests passed, including exact ordered transfer verification and exclusive 0600 receipt creation; changed recovery and a changed temporary source copy stopped before receipt. The real ROM was not modified and no Echo command ran. These fixtures are enabled with ECHOGUIDE_TEST_PINNED_ROM and skip when absent; live staging remains unverified.

Native ROM selection and staging controls now call the checked core APIs; installation requests remain disabled until verified backups and the pinned device-side hash are recorded. The internal guest transport passed eight fixtures with fake SSH/SCP and the read-only pinned payload, including fixed command order, bounded deadlines, trust/artifact checks and unknown-file refusal. A real isolated sleep command confirmed the host deadline. No guest or Echo command ran through this adapter.

Codex v0.162.0-alpha.17.2 completed one genuine MCP powered_wait_status call using ephemeral configuration and a read-only sandbox. No private result content was reproduced and no persistent configuration was changed. This establishes only that narrow tool connection; Claude Desktop and client-driven backups/approval handoffs remain untested.
