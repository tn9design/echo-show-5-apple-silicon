# Source preview implementation results

The integrated app, shared core, CLI and MCP build successfully on the development Mac using local temporary build staging. The expanded run executed 145 XCTest cases with the optional pinned-ROM and pinned-payload fixtures enabled: all passed, none skipped, and no failures. Tests use temporary fixtures, fake runners and isolated host PTYs; they do not connect to an Echo, create a VM, or prove unlock repeatability.

Internal unlock orchestration verifies fresh guest/artifact/device evidence before consuming approval, holds operation ownership across at most three eight-second attempts, permits two-second intervals only after the exact complete rejection, and records the five-minute powered-wait requirement before dispatch. Four fixtures cover rejection bounds, timeout/unexpected/disconnected/cancelled transfer, identity/artifact mismatch and incomplete powered waiting. It never returns unlock success. An internal authenticated guest transport is implemented, but no public live dispatcher is connected to it. The internal fixed one-second powered-wait clock passed three cancellation/timing tests using shortened fixture ticks; its timer remains independent of caller cancellation. Wait records are synchronized before dispatch, and read-only status excludes the private request identifier. A live five-minute device run remains unverified. Independent compatible TWRP verification remains required.

Source packaging now removes Python caches from the disposable copy and CI checks archive paths, symlinks, metadata, required deliverables and signing entitlements. The packaged bounded helper loads its bundled profile in an offline import check; its four metadata tests pass without device commands.

The internal supervised installation workflow now performs fresh recovery, ZIP size/hash and backup checks under operation ownership, consumes approval before wipes, preserves a private synchronized recovery log, and records installation only after reviewed success evidence and accepted reboot. Seven end-to-end fake-device fixtures cover success, changed recovery/ZIP/backups, installer/reboot failures and replay rejection. Startup remains a separate personal confirmation. The native/CLI/MCP live dispatcher is still disabled; no installation was performed during these tests.

Download results are bound to operation IDs, and existing owned directories can be reused while symlinks and regular files are rejected. Diagnostic reports allowlist profile/action labels instead of exporting arbitrary session text; native export captures exactly the displayed preview. Invalid USB plist output reports inspection unavailable, and guest readiness gives separate architecture, translation and SSH explanations. Permission-denied USB inspection still falls under unavailable inspection rather than a separately verified category.
