# Implementation and validation status

This is an experimental source preview, not a finished installer. No live unlock/wipe/install dispatcher is enabled in the app, CLI, or MCP server.

Implemented: shared Swift workflow library; pinned compatibility profile; structured USB enumeration; private persisted sessions and process locks; native approval requests; guided SwiftUI app; profile-based downloads with measured byte progress, cancellation, size/hash validation and safe destinations; CLI and stdio MCP; portable assistant skill; MIT license; source/signing packaging scripts.

Adapters implemented with injectable runners: UTM 5.0.6 owned-VM creation, compatible TWRP identification, named partition discovery, streamed private backups with mount/space/size/hash checks, unique SSH client credentials, VM-bound host-key pinning, verified guest validation asset staging and offline guest readiness. These are exercised with local fixtures. Two distinct managed VM identities are recorded. The first booted through native UTM Run after a scripting timeout; the second passed checked scripting startup and keyboard input after guided input configuration. It is waiting for user-entered Debian account credentials. Neither establishes end-to-end authenticated guest readiness; guest and backup integrations remain unverified.

Internal pilot code integrates approval consumption, fresh recovery/ZIP/backup validation and the supervised installation sequence. Current-invocation recovery log evidence is required; stale successes never authorize reboot. A default-disabled internal dispatcher routes the two actions through fresh host and authenticated guest prerequisites under operation ownership. Internal bounded unlock orchestration records powered-wait intent and requires independent recovery verification; the authenticated guest transport is implemented but has no enabled public dispatcher. The reviewed standalone bounded unlock script remains a separate experimental developer tool with explicit execution, bundled-profile hashes and exact ordinary-rejection classification. It is not called by the GUI/MCP.

The native app exposes read-only authenticated guest fastboot discovery and explicit device selection. Product, locked status and exact bootloader build are checked in the reviewed order before recording compatibility. Listing devices preserves existing identity; failed explicit identification invalidates it. Interrupted-write states cannot be reset by this path. Fixture tests cover these operations; fresh exact UTM ownership reinspection is implemented before and after identification; live identification integration remains unverified.

Still required before Milestone A is complete: fresh managed VM install/input configuration and lifecycle validation; live native serial login and host-key acquisition; end-to-end authenticated guest bootstrap; clean-host and guest-restart checks. The shared engine and app have an explicit memory-only serial login/bootstrap path, bounded PTY transport, challenge-bound identity parsing and client-key installation. Transport tests use isolated host PTYs; protocol tests use fixtures. No live VM bootstrap is proven. The cloud-image provisioning path is deferred until this baseline works. VM creation alone never means guest readiness.

Still required before Milestone B is complete: live authorized recovery/backup validation, live interruption checks, and broader client integration tests. A genuine ephemeral Codex v0.162.0-alpha.17.2 read-only `powered_wait_status` call returned a valid result; Claude Desktop and approval/backup calls remain untested. Structured recovery selection, measured backup progress and explicit interrupted-read reinspection have offline tests. Existing app-owned backup destinations are not overwritten; interrupted partial captures remain incomplete and require a fresh destination.

Still required before Milestone C: live dispatch validation, fresh-VM readiness proof, additional independent device trials, and hardware checks. The app exposes saved powered-wait safety guidance and a checked local ROM chooser/device-side staging action after verified backups; neither enables live unlock/wipe/install dispatch. The existing working Echo is not a test target.

Distribution: no signing identities were available in the inspected host keychain. The packaging script produces source previews without credentials and signs/notarizes only when private identity and notary profile are supplied. Notarization and fresh publisher downloads have not been tested.

The test count and release evidence are recorded in docs/implementation-results.md. Persistent client configuration examples are untested; the narrow ephemeral Codex smoke above does not establish approval, backup, or installation integration.

An internal native confirmation controller binds the displayed device/action/session/evidence and selected local artifacts. It rechecks expiry and prerequisites after confirmation and invalidates the handoff on cancellation or window closure. Its default gate never presents destructive confirmation. The source-preview dialog only reviews or declines requests; production native presentation and dispatch remain unwired.
